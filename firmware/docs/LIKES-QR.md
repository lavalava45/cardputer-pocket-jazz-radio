# Pocket Jazz Radio — от Like к поиску в телефоне

**Статус:** первый QR-поиск включён в **выпущенный immutable v0.7k**: Python 129/129, CTest 21/21, ESP32-S3 компиляция и 3 compile-only PASS. **Физический дисплей/QR/SD/Wi-Fi пока не проверены и установка не разрешена** до измерения APP-слота в M5Launcher PMan. Архивная v0.7j сохраняет только `liked.txt`, без QR-поиска лайков.

**Новый immutable v0.7l:** поиск в Spotify/Google сохранён без API/OAuth; исправлен баг с большим числом **ведущих/конечных пробелов** в ICY (теперь они обрезаются в URL, но **не** меняют сохранённый TSV-журнал). В Velxio действительно виден QR станции и корректная заглушка лайка до первого успешного `K`; сам Spotify QR после успешной записи с SD без аппаратуры не проверен. Следующий независимый этап — [локальный PC-мост для явной копии `liked.txt`](LIKES-PC-BRIDGE.md), ручной проверенной Spotify track URL и HTML/JSON-экспорта. Он **уже реализован**, но автоматической HA/Spotify синхронизации по-прежнему нет.

## Управление в v0.7k (после безопасной аппаратной установки)

1. Когда радио передаёт название композиции (ICY `StreamTitle`), нажать **K** — запись `UTC-время / станция / ICY` добавится в `/PocketJazz/liked.txt` на SD. При ошибке или заполнении журнала поисковый выбор **не обновляется**.
2. Нажать **Q** — первый экран **QR самой радиостанции** (старое поведение).
3. Нажать **Down** — QR-ссылка **Spotify Search** по последнему успешно сохранённому лайку **этого сеанса**; ещё раз Down — обычный **Google Search**. Up листает обратно; Del закрывает.
4. Навести камеру телефона на QR. Поиск открывается в браузере телефона; выбор реальной композиции, нужной версии записи и добавление в Spotify остаются действиями слушателя.

## Честные ограничения

- Не использует Spotify Web API, не запрашивает OAuth и не сохраняет пароль, access token или refresh token. QR содержит **только URL известного поискового сервиса с закодированным названием**, которое уже пришло из радио. После сканирования телефон отправит запрос непосредственно соответствующему сервису.
- Прямой Spotify URL начинается с `https://open.spotify.com/search/`; Google — `https://www.google.com/search?q=`. UTF-8 кодируется через percent-encoding, управляющие байты и повреждённый UTF-8 отвергаются. QR версии 6/ECC medium ограничен **106 байтами**; длинные заголовки сокращаются на границе Unicode-символа с видимой надписью `QUERY SHORTENED`. При сокращении поиск может оказаться неточным.
- Название **не всегда идентифицирует трек**: ICY может сообщать рекламный блок, передачу, альбом или исполнителя вместо песни. Пока нет проверки музыкальных метаданных через внешний каталог и нет автоопределения записи; `track-unknown` намеренно не превращается в поисковую ссылку.
- Последний лайк хранится в RAM только **до перезагрузки**; постоянный журнал на SD остаётся нетронутым. Отображение истории всех лайков/синхронизация с компьютером/HA — отдельный этап. Не читать журнал ради каждого кадра UI и не запускать сеть в аудиоколбэке.
- Ранее существовавший QR прямой ссылки радиостанции **не меняет свой whitelist** (только короткие публичные HTTPS адреса). Внешний search QR формируется исключительно из двух прошитых известных доменов, не из произвольных редиректов/URL вещателя.
- Работоспособность QR, экранной вёрстки на 240×135, камеры телефона, SD append и отсутствие влияния на MP3 ещё нужно подтвердить на физическом Cardputer ADV. **Не устанавливать app-only BIN без подтверждения PMan APP-слота.**
