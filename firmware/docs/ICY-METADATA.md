# ICY StreamTitle и ограничения кодировок — v0.7b

`StreamTitle` — **добровольное поле, присылаемое радиостанцией**, а не подтверждение начала композиции, её автора или названия альбома. Источник может отправлять названия программ, рекламу, повторы, неверную или вовсе отсутствующую информацию. Экран `Y` содержит только историю полученных сообщений играющего потока, а не синхронизированный список всех станций.

## Что меняется в коде v0.7b

- HTTPS `SecureICYSource` использует небольшой **потоковый фиксированный C++-парсер**, без копирования до 4080 байт произвольных ICY-метаданных в динамический `String`. При каждом прочитанном фрагменте поддерживается состояние поля; результат не превышает 95 байт UTF-8 плюс завершающий `NUL`. При битой длине или кавычках заголовок игнорируется, оставшиеся байты ICY должны быть вычитаны до продолжения MP3.
- Заголовок `icy-metaint`: либо отсутствует (нет метаданных), либо **только десятичные цифры 1–1048576**. Отрицательные, неполные или смешанные значения не принимаются. В HTTPS предусмотрен совокупный 2500-мс предел ожидания одного блока ICY между вызовами чтения; при таймауте поток закрывается, а штатная логика радио может выполнить reconnect.
- Общий callback Plain HTTP/HTTPS нормализует текст для UI и последующего ручного экспорта: сохраняет только целые корректные UTF-8 последовательности, заменяет ошибки кодировки/управляющие символы на пробелы и не режет многобайтовый символ в середине. Заранее неизвестную кодировку нельзя достоверно определить из `StreamTitle` — **Latin-1, Windows-1251 и другие не угадываются автоматически**. На станциях со старой однобайтовой кодировкой часть символов может исчезнуть; дальнейший режим с явно заданной кодировкой требует отдельного решения.
- В аудиозадаче нет новых SD/I/O или UI-рисования, фонового опроса других радиостанций нет. Действующая проверка CA/имени TLS-сервера, HTTPS-редиректов, разделение TLS-open и MP3-prefill budget, резервные URL и воспроизведение остаются отдельными контрактами.

## Что не подтверждено

Host C++ регрессии проверяют разбиение ICY-потока на любые границы, повреждённые/переполненные метаданные, UTF-8, строгие интервалы и лимит памяти парсера; Python проверяет фактическую связь его API с HTTPS-источником и callback. Это **не** доказательство фактической работы трансляции, сетевой скорости, корректности всех региональных кодировок или отсутствия underrun на физическом Cardputer ADV. Предыдущая библиотека `AudioFileSourceICYStream` для незашифрованного HTTP остаётся отдельно; её блокирующие чтения требуют дальнейшего исследования и аппаратных проверок. Не изменять её upstream-файлы без самостоятельного тестового gate.

Аппаратные критерии: проверить несколько HTTPS и HTTP MP3 станций, случай с пустым или отсутствующим ICY, повторный reconnect после неполной метаинформации, 15–30 минут устойчивого воспроизведения, значения heap/stack/underrun, экран `Y` и вывод экспортированного TSV. Установка увеличенного BIN требует проверки подходящей непрерывной свободной APP-области через M5Launcher 3 PMan: до этого `NOT CLEARED FOR INSTALL`.
