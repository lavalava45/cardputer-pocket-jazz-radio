# Кандидат v0.7l — проверяемые аудиоисправления после v0.7k

**Статус:** код в рабочем дереве, не означает проверку слухом или физической аппаратуры. Никаких новых размеров ring/prefill/timing в живом радио не выбрано. Исправления локальной копии `ESP8266Audio` распространяются с её GPL-3.0-or-later лицензией в frozen source следующего релиза.

## Подтверждённая программная причинная цепочка

1. В `SecureICYSource.cpp` blocking-read ждёт новые данные до **500 мс** и корректно возвращает нулевой результат при отсутствии доступных TLS-байтов. Это **временное состояние живого MP3-соединения**, не обязательно EOF. Для FIP источник ещё разбирает `Transfer-Encoding: chunked`; для Groove Salad чаще используется ICY-интервал 45000.
2. `AudioFileSourceBuffer::read()` отдаёт то, что в кольцевом буфере, затем прямо дочитывает из источника; при недостаточном наполнении увеличивается статус `UNDERFLOW`. Underflow может быть **без слышимой паузы**, если прямое чтение удовлетворило декодер.
3. В прежнем ESP8266Audio `AudioGeneratorMP3::Input()` при `len == 0 && unused == 0` возвращал `MAD_FLOW_STOP`. Приложение воспринимало выход `decoder->loop() == false` как ошибку, закрывало MP3/HTTPS и запускало новую TLS-сессию. Это **реальный дефект трактовки нулевого чтения**; не доказано, что именно он объясняет все жалобы пользователя.

**Исправление:** необязательный `AudioLiveStallPolicy.h` включается **только в приложении Pocket Jazz** через `decoder->SetLiveStallTimeoutMs(4000)`; все прочие потребители MP3 библиотеки по умолчанию сохраняют обычную EOF-семантику. Пока источник `isOpen()` и размер live-потока неизвестен, краткое нулевое чтение или неполный MP3-кадр переводит декодер в bounded wait (`MAD_FLOW_IGNORE`) без закрытия сокета и без повторного вывода устаревшего PCM. После новых байтов ожидание сбрасывается, а после 4 с непрерывного отсутствия прогресса **реальное переподключение остаётся разрешено**. При ожидании UI честно показывает `BUFFERING`, не `PLAYING`. Размер источника неизвестен, если `getSize()==0` или `UINT32_MAX`; для известного конечного файла этот режим не включается. В `AudioGeneratorMP3::Input()` также устранено чтение `buff[i+1]` на границе полностью заполненного 0x600-байтового буфера синхронизации MP3.

**Второй дефект:** в plain-HTTP `AudioFileSourceICYStream.cpp` три цикла пропуска/сбора ICY метаданных ждали бесконечно, если сервер держал соединение, но перестал передавать bytes. В рабочем коде установлен общий **2500-мс лимит для всего блока**, в каждом из трёх циклов. Лимит проверяется как при нулевом чтении, так и при drip-feed (медленном, но ненулевом ответе). При превышении источник закрывается, передаёт статус NODATA, а основной аудиоконтур имеет возможность восстановить поток или перейти к запасному URL. Для HTTPS `SecureICYSource` уже имел ограничение на метаданные, оно сохранено.

## Проверки и ограничение вывода

- `tests/live_mp3_stall_policy_test.cpp`: 501-мс транзиент, 3999/4000-мс граница, потеря соединения, конечный размер, прогресс между чтениями и `millis()` wraparound — **host-only**.
- `tests/icy_metadata_deadline_test.cpp`: 2500-мс лимит, wraparound — **host-only**. Python-контрактный тест проверяет наличие дедлайна **в начале каждого цикла, включая trickle**. Для доказательства runtime-корректности требуется отдельный mock-тест библиотеки и испытание реального потока; наличие строк исходника — не аппаратная приёмка.
- `tools/probe_station_throughput.py` даёт ограниченный по времени HTTPS-бенчмарк пяти потоков на ПК, не пишет музыкальные байты; результат в `docs/STATION-THROUGHPUT-20261110.json`. Измерение включает TLS/DNS/burst CDN и ICY и **не равно ESP32/MP3 декодированию или audible glitches**.
- На устройстве затем: `I → E` в начале и через 2 минуты для Jazz24/FIP/Groove Salad/Manouche; одновременно слушать реальные прерывания. Фактический APP-слот PMan сначала определить в read-only режиме, не применять изменения flash.

**Неутверждённое:** ни Audio Router SDK, ни SD time-shift worker, ни MQTT и ESP-NOW не подмешиваются в это исправление аудиотракта; один владелец M5.Speaker/ES8311 сохранён.
