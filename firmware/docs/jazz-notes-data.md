# Pocket Jazz Radio — проверяемая база заметок об артистах (v0.3)

**Статус (v0.7b): экспериментальная офлайн-база из 36 проверенных MusicBrainz artist+album пар (33 новых и три исходных).** Firmware уже читает TSV через `N` по `Artist - Track`, проверяет IDX/SHA-256 и использует последовательный поиск при повреждённом индексе. Аппаратный поиск на Cardputer ещё не проверен. Никаких автоматически сочинённых биографий, цитат, историй об альбомах и рекомендаций LLM. Дата проверки и конкретные официальные ссылки — [data/ARTIST-NOTES-PROVENANCE.md](../data/ARTIST-NOTES-PROVENANCE.md).

## Данные и лицензирование

- Первичные ссылки: [MusicBrainz artist](https://musicbrainz.org/doc/MusicBrainz_Entity/Artist) и [MusicBrainz release-group](https://musicbrainz.org/doc/MusicBrainz_Entity/Release_Group). Проверяются два MBID, точное имя артиста, название альбома, `primary-type=Album` и присутствие артиста в `artist-credit` альбома.
- Выводимый короткий текст — **не свободное биографическое описание**. Он собирается только из MusicBrainz *core* fields: instrument relationships, либо дословного поля artist `disambiguation`, плюс годы рождения/смерти или существования группы. Если данные отсутствуют, пишется `instrument not recorded` или `birth unverified`, а не предположение. **Годы жизни не являются датами музыкальной эпохи.**
- Правообладатель/источник метаданных: **MusicBrainz / MetaBrainz Foundation**. Используемые основные данные MusicBrainz — **CC0 1.0** ([официальная лицензия](https://musicbrainz.org/doc/About/Data_License), [разделение core/supplementary](https://musicbrainz.org/doc/MusicBrainz_Database)). Пользовательские теги/жанры, рейтинги и аннотации MusicBrainz исключены: они относятся к supplementary data с **CC BY-NC-SA 3.0**, несовместимыми ограничениями для свободного использования. Википедия и её CC BY-SA-тексты здесь вообще не используются.
- Альбом выбирает **редактор Pocket Jazz**, а не MusicBrainz. MusicBrainz подтверждает только идентичность альбома и связь с артистом, **не качество и не совет его слушать**. Названия и идентификаторы не представляют собой копирование рецензии. Генератор не требует OAuth, API-токенов и личных данных.
- Для API нужен содержательный `User-Agent` с публичным адресом проекта/контакта. Генератор ограничивает обращения до **не более одного запроса в секунду** (интервал 1,2 с); 429/503 обрабатывает с ограниченной повторной попыткой. Используется только официальный MusicBrainz WS/2 JSON поверх HTTPS, **без scraping**. Для коммерческой массовой эксплуатации следует отдельно проверить [условия API](https://musicbrainz.org/doc/MusicBrainz_API), не путать право на CC0 core data с безусловным правом на интенсивную нагрузку публичного API.

## Входной CSV

`data/artists-input.csv`, UTF-8 (заголовок обязателен):

```csv
artist_mbid,artist_name,album_mbid,album_title
561d854a-6a28-4aa7-8c99-323e6ce46c2a,Miles Davis,8e8a594f-2175-38c7-a871-abb68ec363e7,Kind of Blue
```

Одна строка — одна осознанная редакционная рекомендация альбома для одного артиста. MBID артиста и release-group находятся в MusicBrainz. Не вводите выдуманные ID или тексты: генератор отбрасывает несоответствия. Предел 50 входных строк, но **не обещание собрать 50**.

## Выходной TSV

`data/artist-notes.tsv` — готовые к копированию на SD **ASCII-подмножество UTF-8 без BOM**, LF `\n`, **без заголовка**, ровно **7 TAB-разделённых полей**. Источник с не-ASCII текстом отклоняется, а не транслитерируется с потерей смысла:

| № | Поле | Максимум UTF-8 байт | Смысл |
| --- | --- | ---: | --- |
| 1 | `artist_key` | 48 | ASCII slug артиста, например `miles-davis` |
| 2 | `instrument_era` | 108 | Короткая выдержка из core disambiguation или relation с инструментом + **годы жизни/существования**, а не выдуманная эпоха |
| 3 | `album` | 110 | Редакторский выбор, точное MusicBrainz release-group title |
| 4 | `artist_source_url` | 100 | Проверяемый `https://musicbrainz.org/artist/<MBID>` |
| 5 | `album_source_url` | 110 | Проверяемый `https://musicbrainz.org/release-group/<MBID>` |
| 6 | `attribution` | 90 | `MusicBrainz; album picked by Pocket Jazz editor` |
| 7 | `license` | 40 | `MusicBrainz core: CC0-1.0` |

При копировании на microSD ожидаемая пара файлов — `/PocketJazz/artist-notes.tsv` **и** `/PocketJazz/artist-notes.idx`. **Копирование вручную, генератор ничего не устанавливает на устройство.** Уже существующий firmware-парсер ограничивает строки и файлы, отказывается от неверного количества полей для распознавания карточки и безопасно обрабатывает отсутствие файла.

## Индекс v1: `artist-notes.idx`

Компактный текстовый индекс в ASCII, строго LF, без BOM; **заголовок обязателен**, затем записи **отсортированы по беззнаковому `hash32`, при равенстве — по точному `artist_key`**. Хеширование — стандартный FNV-1a 32-bit по ASCII-байтам `artist_key`: инициализация `0x811c9dc5`, для каждого байта `hash = ((hash XOR byte) * 0x01000193) modulo 2^32`. Смещение — **нулевой байтовый offset начала записи в TSV**, не номер строки и не позиция Unicode-символа.

```text
#PJ-NOTES-IDX<TAB>1<TAB>fnv1a32<TAB><sha256-hex-of-exact-tsv-bytes><TAB><row-count>
<8-lowercase-hex-hash><TAB><decimal-byte-offset><TAB><exact-ascii-artist_key>
```

Здесь `<TAB>` обозначает один реальный байт `0x09`. Сумма SHA-256 в заголовке вычисляется по **всему TSV, включая заключительный LF**; количество записей записывается десятичным числом. Ключ хранится целиком, поскольку **совпадающие 32-битные хеши не означают совпадение артистов**. Перед использованием записи клиент должен проверить версию, алгоритм, SHA-256 TSV, корректность порядка, вычисленный хеш и совпадение ключа по извлечённому из TSV адресу; при поиске равных хешей сравнивать **весь** ключ. Индекс не авторизует содержимое сам по себе: достоверность артистов обеспечивается предварительной проверкой MusicBrainz.

**Fallback:** если IDX отсутствует, устарел, повреждён, содержит неизвестную версию, неправильный SHA-256 либо смещение, безопасно **игнорировать индекс и читать TSV последовательным поиском по точному `artist_key`**; отсутствие обоих файлов — «нет заметки», не сбой радио. Обработчик присутствует в firmware, аппаратно пока не проверялся. Некоторые виды повреждений отдельных записей TSV могут оставить базу неполной — проверить на физическом SD.

Пара записывается через временные файлы и `os.replace`: **сначала TSV, затем IDX**. В отличие от атомарной замены одного файла, двухфайловая публикация не является атомарной транзакцией; при прерывании между заменами SHA-256 не позволит принять индекс другой версии. Проверять контрольную сумму следует до использования смещений.
При указании `--output` имя файла обязательно `artist-notes.tsv`, а индекс (`--index`, необязательный аргумент) должен называться `artist-notes.idx` и находиться рядом с TSV — чтобы случайно не перезаписать README, исходники или чужие данные.

## Запуск

Из каталога `apps/pocket-jazz-radio`:

```powershell
python tools/build_jazz_notes.py --self-test
python -m unittest tests/test_jazz_notes_contract.py -v
python tools/build_jazz_notes.py --verify-only
python tools/build_jazz_notes.py
```

`--self-test` использует фиктивные ответы API **только в памяти** и не подтверждает реальные MBID. `--verify-only` обращается к MusicBrainz, но не пишет файлы. Обычный запуск повторно проверяет записи непосредственно через API, создаёт TSV и отсортированный IDX и публикует подготовленную пару. Ошибочные/недоступные записи пропускаются с сообщением; если подтверждённых нет — оба существующих файла сохраняются. Если часть строк пропущена, скрипт возвращает код `2`, чтобы частичный результат нельзя было принять за полностью успешную выборку.

Запрещены TAB, CR/LF, управляющие и форматирующие Unicode-символы, опасные начала spreadsheet-формул, переполнение байтовых лимитов, дубли артиста и некорректные MBID. Поля не обрезаются молча. Повторное использование базы не требует доступа к сети.

**Нормализация и регрессии:** обычные крайние пробелы удаляются, комбинируемые Unicode-символы приводятся к NFC до измерения **байтов** UTF-8; CR/LF и TAB не очищаются молча даже на краях поля, а приводят к отказу записи. Входные CSV с CRLF-разделителями строк допустимы, однако перевод строки *внутри* CSV-поля не допускается к экспорту. Перед сериализацией `render()` повторно проверяет все семь полей, требует ASCII и не принимает ненормализованные записи. `tests/test_jazz_notes_contract.py` проверяет подмену artist/release-group MBID, названия, тип альбома и artist-credit, инъекции, дубликаты, семипольность, известные векторы FNV-1a, реальные байтовые смещения в TSV, неверные хеши/ключи/заголовки, индекс с неверной SHA-256, атомарную подготовку пары и отсутствие индекса. Эти тесты полностью автономны. **Соответствие сохранённых данных текущему MusicBrainz API** устанавливается отдельно через `--verify-only`, а не подменяется тестовыми фикстурами.

**Ограничения:** API может быть временно недоступен, а core disambiguation иногда неполон. Отсутствие подтверждённого инструмента предпочтительнее ложной «биографии». Проверка на Cardputer ADV, фактические размеры строк в UI и совместимость будущего парсера — отдельные задачи v0.3.
