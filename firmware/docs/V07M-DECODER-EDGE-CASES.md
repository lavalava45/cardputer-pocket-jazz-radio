# Pocket Jazz Radio — дополнительные MP3/ICY граничные случаи после v0.7l

**Исходное состояние:** immutable v0.7l успешно проходит host/ESP32 compile gate и загружается в Velxio; её настоящая MP3/ES8311 нагрузка на Cardputer пока **не измерена**. Следующие улучшения **не принадлежат** v0.7l и требуют нового полного release gate; не подменять утверждениями о физическом воспроизведении.

## 1. MPEG sync на границе TCP read

В старом `AudioGeneratorMP3::Input()` поток сканировался по парам байтов `0xFF/0xE0+`. При заполнении 1536-байтового буфера проверка последнего `buff[i+1]` читала за пределом массива. Простая замена цикла на `i+1 < len` исправляет выход за границу, но оставляет **сегментированный MPEG-header**: если последний байт пакета `FF`, а первый следующего `FB`, оба байта никогда не анализируются вместе.

В локальном GPL-совместимом helper `AudioMp3SyncBoundary.h` теперь используются `findSyncHeader()` и `carryPartialSync()`. При отсутствии полного заголовка сохраняется **только последний `FF`**, и следующая порция сети добавляется к нему. Ни дополнительная динамическая память, ни изменение 32-КБ stream ring не требуются. Реальная функция вызывается в `AudioGeneratorMP3::Input()`; host C++ test `mp3_sync_fragment_test.cpp` даёт фрагменты `junk FF | FB valid`, полностью заполненный 1536-Б массив, EOF/small/null и отсутствие ложного sync.

## 2. Положительный мусор не должен бесконечно продлевать ожидание

В v0.7l отсутствие *любых* байтов ограничено 4000 мс, но `progress()` отмечал **каждый положительный read**, даже единственный повреждённый byte. Бесконечная последовательность неверных данных могла вечно сбрасывать срок ожидания при отсутствии декодируемых кадров. Исправлено отдельным `AudioLiveFrameWatchdog`, который **сбрасывается только после успешного `mad_frame_decode`**, а не после транспортного приёма. Для Pocket Jazz максимальное ожидание без валидного кадра = **3 × 4000 = 12000 мс** — явная защитная граница, не эмпирическая настройка качества музыки. Проверка выполняется как между кадрами, так и в цикле поиска sync, чтобы поток мусора не блокировал аудиозадачу. Другие приложения библиотеки без `SetLiveStallTimeoutMs()` этой политики не получают. Срок rollover-safe по `uint32_t millis()`.

Эти 12 секунд — верхняя граница восстановления **невалидного контента**; они не гарантируют, что пропуски аудио короче 12 секунд будут не слышны. Если сервер не присылает MP3 после этого срока, radio task может закрыть источник и выполнить обычный failover/reconnect.

## 3. ICY metadata медленно, но не нулевым read

В v0.7l у plain-HTTP `AudioFileSourceICYStream` deadline проверялся только в ветках `ret==0`. Если вещатель бесконечно отдаёт по одному байту через короткие интервалы, цикл мог прожить намного дольше 2,5 с. В новой версии проверка **абсолютного срока** добавлена **в начало всех трёх metadata-циклов**, до нового чтения. При истечении сроков source.close делает `http.end()` и сообщает `STATUS_NODATA`. HTTPS-парсер уже имел собственный ограниченный lifecycle; не отключена проверка доверенных сертификатов.

## 4. Независимые инженерные проверки

- Реальные вызовы helper для MP3 sync испытываются через `tests/mp3_sync_fragment_test.cpp`.
- Срок без полезных кадров испытывается в `tests/live_mp3_stall_policy_test.cpp`: входящие junk-байты не сбрасывают last decoded frame, тестируется wrap-around `millis()` и отключённая по умолчанию политика.
- Дедлайн ICY покрыт `tests/icy_metadata_deadline_test.cpp` и Python source-contract: все три цикла проверяют время до read, в том числе при drip-feed.
- Транспортные исследования пяти внешних потоков сохранены в `STATION-THROUGHPUT-20261110.json`. Это **данные ПК**, не воспроизведение звука.
- В рамках time-shift `TimeShiftHostFileStore.h` принимает только заранее подготовленный FILE*, запрещает resize и переходит в fail-closed при I/O сбое; это **не SD worker, не ring эфира, не автозапись**.

**Обязательная оставшаяся проверка:** read-only размер APP-слота в PMan, затем реальный Cardputer с наблюдением фактических ΔUnderruns, Buffer, reconnect и слышимых пауз Groove Salad/FIP/Jazz24/Manouche. Никаких действий с M5Launcher, bootloader, partition table и SD в этих исправлениях нет.
