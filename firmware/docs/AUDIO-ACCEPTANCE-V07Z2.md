# Pocket Jazz Radio v0.7z2 — минимальная информативная аппаратная приёмка

**СТАТУС: ПЛАН, НЕ ВЫПОЛНЕНО.** Host Python/MSVC/Arduino compile не являются доказательством звука на физическом Cardputer ADV. Пользовательские наблюдения v0.7v уже сохранены в [HARDWARE-OBSERVATIONS-20261110](HARDWARE-OBSERVATIONS-20261110.md), включая Swiss Jazz DIRECT/REDIRECT FAIL, TSF FAIL, KJazz FAIL, паузы Bossa Beyond/181.fm и ранее работавшую WRTI. **Старые DIRECT/REDIRECT A/B не повторять.**

## Установка — только после read-only проверки PMan

1. Проверить на существующем M5Launcher 3/PMan **фактический размер доступного APP-раздела** и сравнить с *реальным размером BIN нового релиза*, который появится в его manifest. Предыдущая v0.7z1 имела app-only **1 576 448 Б**, выше консервативного лимита **1 376 256 Б**. Без достаточного APP-слота **не устанавливать**, не переразмечать flash, не менять M5Launcher 3 и не использовать full-flash образ.
2. Только при достаточном слоте **вручную** загрузить app-only BIN как обычную SD-программу M5Launcher; не импортировать и не перезаписывать `04-my-stations.m3u`, личные MP3, настройки, NVS или другую SD.
3. На `H` или `I` убедиться, что на LCD показана **точная установленная версия v0.7z2**, а не v0.7v/v0.7z1. Записать версию и сеть/RSSI. Не объявлять отсутствие звука доказательством ошибки нового кода, если установлена другая версия.

## Первичные 2 станции, несколько минут, без повторения старого A/B

Выбрать одну из **Swiss Jazz / TSF Jazz France** (прежний HTTPS FAIL) и одну из **Bossa Beyond / 181.fm** (ранее PCM dropouts). Проверять только при нормальном Wi-Fi и синхронизированном NTP (`I`: `WiFi STABLE`, `NTP SYNCED`). Перед каждым потоком на Diagnostics нажать `X`, чтобы обнулить **отображаемые** максимумы и эпизоды.

| Когда | Что зафиксировать | Где |
| --- | --- | --- |
| Сразу после запуска | Версия, станция, RSSI, `CONNECTING/BUFFERING/ON AIR`, появился ли MP3 PCM | `H`, радио, `I` |
| После 1–2 минут | Непрерывное слышимое воспроизведение; количество/максимум цифровых PCM-gap, `Under`, текущий `Buf` | Слух + `I → Down` |
| По HTTPS | `phase/hop`, DNS/TCP+TLS/GET ms, largest before/after, `Buf min`, UIgap | `I → Down×3` |
| При заметной паузе | Максимальная длительность `Source pull`, `MP3 loop`, `PCM flush` (все мкс), `UIgap` (мс), `Under/Buf` | **`I → Down×4`** |
| Во время нового CONNECTING | Попробовать только изменение громкости — не должно вызывать новый сетевой reopen | Радио, `I → Down` Opens |
| Отдельно | STOP и смена станции во время CONNECTING, время возврата; не требовать мгновенной отмены уже выполняющегося синхронного GET | `I → Down` STOP ms, наблюдение |

**Интерпретация (только ориентиры, не автоматическое заключение):** высокий `Source pull` указывает на время в сети/TLS/ICY, высокий `MP3 loop` при низком `Source pull` — на decode или speaker wait, высокий `PCM flush` — на ожидание доступа к PCM-блокам/M5.Speaker; высокий `UIgap` при всех низких аудиопоказателях требует отдельного профилирования UI/Wi-Fi/SD. `PCM flush` — время **включая playRaw и ожидание callback**, а не факт воспроизведения из динамика. `TLS raw` **положительное** значение (включая 9984 и 35512) не является доказанным отказом сертификата.

Если обе станции стабильно играют, затем проверять **пять разнотипных MP3-станций по 30 минут**, после этого ≥2 часа непрерывно, Wi-Fi reconnect, cold boot/NTP/две Wi-Fi сети, offline MP3, Backup (только вручную), Clock/Blue Note, будильник, Likes/QR, Notes/Spark, мультимодальные клавиши и реальную SD latency. Не объявлять hardware PASS по одной WRTI или host-тестам. Любой новый дефект фиксировать как `версия / станция / время / Wi-Fi RSSI / HTTPS phase / Source pull / MP3 loop / PCM flush / Buf min / Under / PCM gap / UIgap / слышимая пауза`.
