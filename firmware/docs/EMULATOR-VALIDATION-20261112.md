# Эмуляторы Pocket Jazz / TLS RAM — практическая проверка 12.11.2026

## Дополнительная проверка именно v0.7z5 (после выпуска)

**Запуск полного 8-МБ merged-образа v0.7z5 в esp-emulator v0.51.0 с PSRAM=0 выполнен.** Программа загрузила ROM/bootloader ESP32-S3, но после entry `0x403c88b8` снова получено `[error] Keyboard: Unsupported board type: 137`. Лог: `out/espemu-v07z5-full-boot.log`. **Само приложение не дошло до работающего аудиотракта**. Входящий в merged образ app побайтово совпадает с `dist/releases/0.7z5/firmware/PocketJazzRadio-v0.7z5-app-only.bin` со смещения `0x10000`; SHA app `6983c0d82ba14ecf87a0544adb006a3828f2048756b18069a299bc2f9a715ba4`. Тестовый merged **не предназначен для записи на настоящий Cardputer**.

**Новый целевой эксперимент:** `experiments/TlsHeapProbeZ5/TlsHeapProbeZ5.ino` создан отдельно от основного приложения и релизных исходников. Сборка Arduino-ESP32-S3 (m5stack core 3.3.9), flash 8 MB, PSRAM disabled, **PASS**. Добавлена `volatile` статическая нагрузка **68 000 Б**, поэтому итоговая статическая RAM скетча **113 876 Б** против **114 044 Б** у v0.7z5 (различие 168 Б по общему размеру; **это не идентичное распределение**). Скетч использует исходный набор 4-root CA `RadioTrustedRoots.h`, штатную проверку имени хоста, Wi-Fi SoftAP эмулятора и прямое защищённое подключение к `stream.srg-ssr.ch:443`; нет `setInsecure`, реального пароля или обращения к пользовательским NVS/SD. Время установлено только внутри теста.

**Проверен конкретный порядок из v0.7z5:** `malloc(32768)` **до** TLS; открытый TLS-сокет остаётся в памяти; `malloc(29192)` для декодера **после успешного TLS**, до закрытия защищённого соединения. Измерения одного холодного запуска:

| Фаза | Свободная внутренняя RAM | Крупнейший свободный 8-bit блок |
| --- | ---: | ---: |
| После Wi-Fi, до MP3 | 201 500 Б | 155 636 Б |
| MP3 ring зарезервирован, TLS ещё не начат | 166 680 Б | 122 868 Б |
| TLS соединён, ring удерживается | **118 080 Б** | **57 332 Б** |
| TLS остаётся открытым, codec выделен | **88 380 Б** | **31 732 Б** |
| TLS остановлен, ring/codec освобождены | 198 796 Б | 114 676 Б |

Исходное защищённое соединение **PASS за 757 мс** (наблюдавшийся `raw=+48` — не отрицательная ошибка SSL). Оба `malloc` прошли, `DONE ringOK=1 tlsOK=1 codecOK=1`. Примечательная особенность: после выделения **обоих** блоков в эмуляторе крупнейший оставшийся блок = **31 732 Б** — точно столько же, сколько было **после TLS, но до MP3 ring** на реальном v0.7z4. Это иллюстрирует, насколько важно, **на каком этапе** выполняется крупная аллокация; само совпадение числа не доказывает идентичную модель памяти.

Лог: `out/espemu-v07z5-tlsprobe-run.log`. Эмуляторная конфигурация `--chip esp32s3 --psram-size 0 --net user --wifi-ssid PJTEST --wifi-password PJTEST123`. **Уровень доказательства: TLS/allocator в тестовом скетче; НЕ декодирование/PCM/SD/экран настоящего радио.** Динамическая heap-фрагментация, задачи, Wi-Fi/NVS, работа M5-периферии и повторные открытия в основном приложении не воспроизведены.

**Повторяемость:** провёл ещё два *независимых холодных старта* того же теста (логи `out/espemu-v07z5-tlsprobe-run-2.log`, `out/espemu-v07z5-tlsprobe-run-3.log`). В трёх запусках **3/3 Wi-Fi PASS, TLS PASS и codec malloc PASS**, финальный маркер `DONE ringOK=1 tlsOK=1 codecOK=1` присутствует в каждом. Времена TLS: **757 / 535 / 673 мс** соответственно. Это свидетельствует о повторяемости эксперимента, не об исправлении реального аудиотракта.

**Задача:** проверять ситуацию `MBEDTLS_ERR_SSL_ALLOC_FAILED (-0x7F00)` на ESP32-S3 без изменения физического Cardputer, а не только LCD/Help.

## Выбор

1. **Espressif [esp-emulator](https://github.com/espressif/esp-emulator) v0.51.0** — выбран для воспроизведения внутренних RAM-ограничений, реального Xtensa LX7 boot, Wi-Fi и TLS. Запускается в WSL Ubuntu. Умеет `--psram-size 0`, внутренние region maps, ROM boot, NAT и Wi-Fi SoftAP. Официальный бинарник x86_64 с GitHub Releases проверен по опубликованному `SHA256SUMS`: `2b9e157470edb8b03167996550292c6df8cc6716025ebad8927db950d7931417`, сохранён в `out/esp-emulator-v0.51.0/`, глобальная система не изменялась. Это **не** автоматическое доказательство идентичности allocator, CPU timing, NVS, драйверов M5/ES8311 и физической RAM при аудионагрузке.
2. **[Velxio Cardputer ADV](https://velxio.dev/m5stack-cardputer-simulator/)** — предыдущие v0.7k/v0.7l действительно запускались с LCD/Help/клавишами. В текущей проверке v0.7z4 через browser-controlled File→Upload firmware открытие системного file picker не подтвердилось. Попытка прямой передачи локального 8-МБ merged через локальный сервер в страницу Velxio была заблокирована Chrome `Permission was denied ... loopback address space`; **тест новой прошивки в Velxio не состоялся**. Публичная страница Velxio указывает виртуальные 8 MB PSRAM и 16 MB flash — **не переносить автоматически** эту конфигурацию на наше Cardputer ADV (проект компилируется с 8 MB flash, PSRAM disabled). Поэтому нельзя пользоваться цифрами Velxio для вывода о физическом TLS heap.
3. **[Espressif QEMU ESP32-S3](https://github.com/espressif/esp-toolchain-docs/tree/main/qemu/esp32s3)** — полезен для CPU/FreeRTOS/памяти, но типовой документированный network-backend использует виртуальный OpenETH, а не наш Wi-Fi/ES8311. Менее прямой путь для этого сбоя, чем esp-emulator.
4. **[Wokwi ESP32-S3](https://docs.wokwi.com/getting-started/supported-hardware)** — ESP32-S3 поддерживается, но точность heap и компонентов M5 для нашего конкретного отказа не подтверждена.

## Реальный запуск полной v0.7z4

Собранный только для эмуляции полный **8 388 608-Б** merged `dist/build/PocketJazzRadio.ino.merged.bin` проверен: APP-область со смещения `0x10000` **побайтово совпала** с immutable `dist/releases/0.7z4/firmware/PocketJazzRadio-v0.7z4-app-only.bin`. Запущено WSL:

```sh
esp-emu --chip esp32s3 --firmware PocketJazzRadio.ino.merged.bin --psram-size 0 \
  --net user --wifi-ssid PJTEST --wifi-password PJTEST123 --timeout 12s
```

**Фактически:** emu загрузил 8 MB flash, реальный ROM ESP32-S3 и bootloader, показал `PSRAM configured as 0 KB` и ROM boot до `entry 0x403c88b8`. Далее приложение вывело `[error] Keyboard: Unsupported board type: 137`. **Полноценного экрана/сети/звука нашего Pocket Jazz в этом запуске не было**; emulator не является drop-in заменой M5Cardputer/LCD/ES8311.

## Репрезентативный минимальный TLS/RAM эксперимент

Создан **только для эмулятора** `experiments/TlsHeapProbe/TlsHeapProbe.ino`, собран настоящим `arduino-cli` для `m5stack_cardputer`, `PSRAM=disabled`, с импортом **неизменённого `RadioTrustedRoots.h`**. Никакого `setInsecure()`, реальных Wi-Fi-паролей, NVS и записи на физический ADV. В прошивке две последовательные проверки на **одном** перезапуске. Тестовая Wi-Fi сеть `PJTEST` эмулируется внутри esp-emu; время 12.11.2026 задаётся только в тесте, чтобы не ослаблять валидацию сертификатов из-за отсутствующего NTP.

**Фактический вывод** (`out/espemu-tls-heap-probe-run.log`):

| Параметр | Сначала выделены ring+codec | TLS раньше MP3 ring+codec |
| --- | ---: | ---: |
| Свободная внутренняя RAM до TLS | 206 564 Б | 269 568 Б |
| Largest free block до TLS | 163 828 Б | 116 724 Б |
| TLS соединение с `stream.srg-ssr.ch:443` | **PASS** | **PASS** |
| Длительность TLS | 694 мс | 836 мс |
| Валидация CA/hostname | штатная | штатная |
| Выделение двух MP3-буферов после TLS | не применимо | **PASS** |

Исходно без буферов внутренняя free heap **270 060 Б**, largest **225 268 Б**. Старые предварительные аллокации 32 768 + 29 192 Б прошли; после старого TLS было **159 208 Б free**, largest **98 292 Б**. После stop и free стало 269 568 Б free, но largest **только 116 724 Б**: **фрагментация после первого сценария меняет условия второго**, поэтому это не корректный рандомизированный A/B и нельзя сравнивать только largest между двумя строками. Во втором сценарии оба буфера успешно выделились после TLS, код ошибки `raw=+48` — не `-0x7F00`.

**Вывод:** официальная симуляция действительно запускает сетевой/TLS стек ESP32-S3 с нашим CA bundle и поддерживает heap-инструментацию; **ошибка `-32512` в минимальном тесте НЕ воспроизведена**. В полном радио статической RAM и дополнительных задач/сокетов намного больше, чем в тестовом скетче (у полного firmware static RAM 114 044 Б, у fixture 45 876 Б), поэтому оба успешных TLS не доказывают исправления полного радиотракта.

**Следующий наиболее информативный этап:** физическая v0.7z4 с `MEMORY 7/8` и `SYSTEM HEALTH 8/8`, TSV-экспорт. Если ошибка останется, добавить test-only allocator pressure/fault injection с одинаковым объёмом RAM и повторяемыми холодными загрузками в esp-emulator. Не уменьшать CA, timeout и prefill ради того, чтобы пройти эмулятор.

**Безопасность:** никогда не устанавливать `*.merged.bin` из `dist/build` на настоящий Cardputer/M5Launcher; пользовательский BIN только `dist/releases/0.7z4/firmware/*-app-only.bin`. Тест использует disposable виртуальные credentials.

## Дополнение после v0.7z6: автоматический тест непрерывности и восстановления

Отдельно создан и **успешно собран и запущен** `experiments/AudioContinuityProbe/`.
В нём используются текущие `SecureICYSource`, CA/hostname TLS, ICY,
`AudioFileSourceBuffer`, `Mp3CodecWorkspace`, ESP8266Audio/libmad;
8 вспомогательных исходников идентичны текущему приложению по SHA-256.
Установки на физический Cardputer не было. Эмулятор `esp-emu v0.51.0`,
S3 без PSRAM, globals fixture=114164 Б против globals v0.7z6=114044 Б
(это **не** идентичный layout полной прошивки).

Проверенный лог: `out/audio-continuity/smoke-final.log`.
`SUITE_DONE passed=4 failed=0`: Sonic baseline 8 с (max PCM gap 12 мс),
искусственная 1500-мс пауза plaintext-MP3-read (наблюдаемый PCM gap
1013 мс, после паузы PCM восстановился), принудительное закрытие реального
TLS-сокета после 16384 Б (декодер остановился), новый HTTPS Sonic после
закрытия (max PCM gap 12 мс, снова есть PCM). После cleanup свободно
около 201 КБ; largest зависит от последовательности (118772–155636 Б).

**Не установлено:** причина спонтанного первого обрыва на физическом ADV,
реальный I2S/M5Speaker, конкуренция задач/UI/PEEK, многократная
100-cycle фрагментация и непрерывный 30-минутный прогон. PCM sink
имеет только приближённый pacing по блокам и не эмулирует аудиовыход.
Полная таблица, команды и ограничения:
`experiments/AudioContinuityProbe/RESULTS-20261112.md` и `README.md`.

**13.11.2026, аппаратный TSV и малопамятный сценарий:** разбор двух
16-событийных экспортов `audio-runtime.tsv` в
`docs/AUDIO-RUNTIME-TSV-ANALYSIS-20261113.md`.
Реальное устройство подтвердило `MBEDTLS_ERR_SSL_ALLOC_FAILED=-32512`
на повторных TLS-открытиях при largest_before=19444 Б; отдельный отрезок
показал истощение MP3-входного буфера при ~8.6 КБ свободной RAM и
largest=1332 Б, но не причину этого истощения. Тестовый стенд расширен до
5 сценариев; при искусственном free=10636/largest=6132 Б эмулятор
продолжал выдавать PCM без длинных промежутков (max=13 мс, 8 с).
Этот результат **не позволяет приписать первоначальный обрыв одной
только величине heap**. Лог `out/audio-continuity/smoke-heap-pressure.log`.
