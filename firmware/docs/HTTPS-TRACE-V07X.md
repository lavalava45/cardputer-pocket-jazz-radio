# Диагностическая трасса HTTPS/MP3 — v0.7x (программный эксперимент)

## Зачем

На физической v0.7v Swiss Jazz DIRECT и REDIRECT, TSF Jazz и KJazz Los Angeles не подключались; другие станции прерывались на несколько секунд, росли `Under` и `PCM gap`, а прокрутка имени дёргалась во время reconnect. v0.7w — самостоятельный каталог/сброс счётчиков, не исправление аудио; его физические результаты не подтверждены. Различать ошибку конкретного URL и общего транспорта без нового эксперимента на устройстве нельзя.

## Новые числовые поля (I → Down ×3, страница 4)

`HTTPS phase` — **последняя попытка**, `hop` — номер HTTP-запроса в цепочке redirect, начиная с 1. Значения: `0` нет попытки, `1` неверный URL/сертификат/часы, `2` HTTPClient.begin, `3` DNS, `4` TCP+TLS, `5` проверка соединения после успешного secure connect, `6` обработка HTTP ответа/заголовков, `7` HTTP 200. При последующей ошибке чтения/MP3 фаза `7` может сохраняться: это **не** подтверждение стабильного эфира.

`DNS` и `TCP+TLS`: `-1` не было попытки, `0` не удалось, `1` успех; рядом длительность каждого этапа, мс. TCP и TLS **не разделены**: публичный SDK требует отдельной instrumented-сборки для достоверного разнесения. Внутри существующего secure client выполняется один DNS lookup, затем один TCP+TLS через `NetworkClientSecure::connect(IP,port,original-host,CA,...)` — **SNI, проверка доменного имени и CA сохраняются**. Дополнительный test-connection/HTTP-запрос к станции не отправляется. `GET total` — длительность запроса, включая DNS, secure connect и заголовки HTTP; отдельные цифры не обязаны складываться точно.

`Before heap/max` и `After heap/max` — 8-bit-capable heap и его крупнейший непрерывный блок **непосредственно перед TCP/TLS и после результата**. Если DNS завершился ошибкой, поля остаются `0/0`, что **не означает исчерпание памяти**. Измерения не охватывают каждый внутренний пик во время TLS handshake. Значения относятся к последнему hop, а не ко всем hop цепочки.

`Buf min` — минимум compressed-MP3 ring **с момента последнего успешного prefill** и время его первого достижения (секунды uptime), `UIgap` — наибольший интервал между входами в UI `loop()` в мс с момента загрузки или `X`. `Buf min=0` при STOP/ошибке/ещё не созданном буфере — сброс состояния, а **не** доказанное переполнение/опустошение сети. `Buf` на странице 2 — текущий снимок после шага декодера; при уничтожении буфера обе метрики обнуляются. `Under` по-прежнему означает buffer short-read episodes, `PCM gap` — цифровой handoff gap, а не акустическое измерение.

Прежнее `TLS raw` — значение SDK `lastError()` (может быть положительным FD, не «номер ошибки»). Фазовое поле `5` может означать, что secure connect сообщил успех, но `HTTPClient::connected()` отказал, не доказательство сбоя сертификата.

## Ограничения и цель минимального физического теста

Диагностика добавлена только к существующему HTTPS-аудиоклиенту; не меняет MP3 ring 32768 B, prefill 2048 B, тайм-ауты, CA, playlist URL, SD/NVS, таблицу разделов, загрузчик, audio-worker priority или отдельный ESP32 SDK. Не обещает исправить заикания. Модельный/host PASS **не** означает аппаратный PASS.

При ручном запуске v0.7x через M5Launcher 3 достаточно одного неработающего HTTPS-потока (например, Swiss Jazz) и одной заикающейся станции: после попытки открыть `I → Down ×3`, выписать семь строк страницы 4 и на странице 2 `Fail`, `Buf`, `Under`, `PCM gap`. Многократные тесты DIRECT/REDIRECT не нужны: они уже были сделаны и оба провалились. Если UI снова зависает, `UIgap` сохраняет максимальный интервал, а экран в покое не требует наблюдать скролл. Любые исправления звука — только после классификации этого результата или отдельного обоснованного аудита кода.
