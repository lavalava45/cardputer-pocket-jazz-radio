# Pocket Jazz Radio — добровольный офлайн-мост лайков для ПК

**Невыпущенный кандидат после v0.7m — защита от потери локальных данных:** в `tools/likes_bridge.py` введена **межпроцессная lock-защита** `ingest`, `confirm`, `skip`, `export`. Если другой процесс уже обрабатывает те же данные, операция завершится без изменения состояния и попросит повторить позже. В папке рядом с JSON остаётся маленький `.likes-state.json.pocketjazz.lock`; **его не удалять**, особенно при запущенном импорте. Для HTML/JSON отчётов создаётся аналогичный sidecar. `export --replace` теперь **откажется перезаписать неизвестный файл, другой likes-state.json или старый отчёт без идентификатора версии** — выберите новый filename для устаревшего отчёта; старое содержимое сохраняется. Новые отчёты помечены `pocketjazz-likes-report-v1`. Нет секретов, фоновых задач, Spotify OAuth или автоматической HA-публикации. Затронутые тесты 14/14 PASS; полного нового Arduino gate пока нет.

**Состояние после v0.7k:** новый независимый инструмент `tools/likes_bridge.py`, не интегрирован в ESP32-прошивку и не требует отдельного сервера. В отличие от QR-поиска v0.7k он может прочитать **всю историю** лайков, но только из **явно скопированного** пользователем `liked.txt`.

## Пример запуска на Windows

Рабочая папка: `E:\Downloads\devspace-test\cardputer-adv\apps\pocket-jazz-radio`.

1. **Скопировать** с microSD `/PocketJazz/liked.txt` в выбранную локальную папку (например `E:\Downloads\PocketJazz-Copy\liked.txt`). Не работать с оригинальным путём на SD и не перемещать сам файл.
2. Один раз импортировать копию:

   `python tools/likes_bridge.py ingest --source "E:\Downloads\PocketJazz-Copy\liked.txt" --state "E:\Downloads\PocketJazz-Copy\likes-state.json"`

3. Сгенерировать **офлайн HTML** с поиском Spotify/Google и ссылками для ручной сверки:

   `python tools/likes_bridge.py export --state "E:\Downloads\PocketJazz-Copy\likes-state.json" --output "E:\Downloads\PocketJazz-Copy\likes-review.html"`

   Открыть `likes-review.html` в браузере. Файл содержит видимые названия, даты, станции, статус и ID события. **Поиск — только подсказка**, не подтверждение записи.

4. После визуальной проверки результата Spotify (исполнитель, версия, кавер, ремастер, концерт) сохранить конкретную ссылку **вручную**:

   `python tools/likes_bridge.py confirm --state "E:\Downloads\PocketJazz-Copy\likes-state.json" --id <24-значный ID из HTML> --url https://open.spotify.com/track/<22-значный ID>`

   Для неподходящей записи вместо confirm: `python tools/likes_bridge.py skip --state "E:\Downloads\PocketJazz-Copy\likes-state.json" --id <ID>`.

5. После **следующего копирования полного обновлённого `liked.txt`** повторить ingest. При неизменном файле ничего не добавится; новые строки импортируются, старые ручные подтверждения не сбрасываются. Для обновления уже созданного HTML использовать `export ... --replace`; по умолчанию инструмент запрещает случайную перезапись файла.

6. Для возможного будущего **явно подключаемого** HA/ПК-посредника получить JSON вместо HTML: `python tools/likes_bridge.py export --state ... --output "...\likes-feed.json"`. Это лишь локальный файл данных, **не MQTT-публикация, не HA-интеграция, не Spotify OAuth**.

## Правила и ограничения

- Импорт ожидает **три TSV-поля**: `YYYY-MM-DDTHH:MMZ` или `time-unknown`, имя станции (до 55 Б), ICY-заголовок (до 95 Б), завершающий перевод строки. Максимальный размер `liked.txt` — **64 КиБ**, допустимых записей не более 800. UTF-8 строго проверяется; при не-UTF-8 или повреждённом/неполном хвосте операция **завершается без обновления состояния**. У разных эфирных станций ICY может быть рекламой или названием передачи.
- Хэш содержимого ранее импортированного префикса защищает от случайной смены/ротации источника; **передача только дописанного файла**. Повтор одинаковой строки считается отдельным событием, но повторный импорт того же файла не дублирует события. Хэш — проверка целостности и идемпотентности, не криптографическая подпись происхождения.
- Состояние `likes-state.json` сохраняется атомарной заменой во **вновь выбранной локальной папке**, а не на SD. До 2 МиБ, версия схемы 1. Если оригинальный журнал на SD станет полным, мост не меняет его и не удаляет записи.
- HTML экранирует тексты станции/ICY и запрещает referrer при открытии ссылок. Никаких <escape><script></escape>-вставок из данных, сетевых запросов без щелчка, локальных слушателей/серверов, OAuth-токенов, секретов, скриптов добавления песен и сторонних зависимостей.
- `confirm` принимает только строгий HTTPS-URL `open.spotify.com/track/` с 22-буквенно-цифровым ID. Это **ручная запись намерения/выбранного совпадения**, программа **не проверяет существование этого ID у Spotify**, не добавляет его в плейлист.
- Позднее можно добавить LAN/HA-мост с явным opt-in, защищённым каналом и отдельной авторизацией; сейчас инструмент работает полностью локально и **ни одного нового постоянного процесса на ПК не создаёт**.

## Проверки

Юнит-тесты в `tests/test_likes_bridge.py` проверяют повторный импорт, неоднозначные одинаковые строки, оборванный лог, подменённый префикс, UTF-8, ограничения размера, враждебные URL/HTML и атомарное поведение при повреждённом JSON. Включены в общий Python gate; **реальное содержимое пользовательской SD не считывалось и не менялось**.
